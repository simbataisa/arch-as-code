01 Scope

What landed

A complete testing strategy corpus, organised by how something is verified rather than which product domain it belongs to. Two patterns from unrelated domains that fail the same way — a ledger invariant and a position-keeping invariant, say — now share one archetype, because the test design that catches one catches the other.

03 Where it earned its keep

Family F — the two security archetypes

Every other archetype needed one review pass. Both security documents required a mandatory InfoSec review before Status: Approved, and both came back with real findings — this is where the process actually caught things worth catching.

TST-040 AuthN/AuthZ Matrix & Token Lifecycle
Round 1 review — 10 required findings

An oracle scored a crashed policy engine as a passing "deny"; a gateway-bypass check could report green even when both paths were wrong the same way; a JMeter harness section rested on a false claim about JMeter's own capabilities.

Round 1 fix — partial

Nine of ten findings resolved cleanly. The tenth — a clock-skew check — cited a pattern document that turned out not to declare the value it claimed to.

Round 2 fix + re-review — approved

JMeter's real capabilities verified directly rather than assumed; the fabricated cross-link replaced with a genuine runtime measurement. The reviewer went in expecting to fail one specific claim and found itself wrong instead.

TST-041 Data Protection, Masking & Tokenisation
Round 1 review — 13 required findings, 4 hard blockers

A collision check that was mathematically meaningless against the algorithm actually in use; an audit-log tamper check missing the pattern's own named anti-tamper mechanism; a secure-storage check trivially true even on a fully compromised device; a push-notification content check built as a deny-list where the pattern declares an allow-list.

Round 1 fix — all 13 resolved

Invariant set restructured from 9 to 11 checks, each re-derived from the actual pattern document rather than the review's paraphrase of it.

Re-review — one new finding

A genuine race condition in a test script's concurrency handling, missed on the first pass.

Round 2 fix — approved

Resolved with a one-line atomic-operation swap. All 14 findings, across both rounds, independently re-verified against source before sign-off.

04 What "mechanical" tasks caught

Registration and coverage completion

Cataloguing the two approved security archetypes, and later filling the coverage file for every remaining row, looked like low-risk bookkeeping. Direct verification — rather than trusting a clean-sounding report — caught real defects each time anyway.

Found during catalog registration

An empty compliance field on an archetype that already had a full, approved compliance section; five stale "reserved for a future wave" notes outliving the wave they described; a structural bug duplicating two archetypes into the wrong family's table.

Found at the final gate — on the report author's own side

A broken link assumed, across many prior tasks, to be pre-existing baseline noise turned out to be a defect introduced by this plan's own early work — confirmed against git history and fixed before merge.
