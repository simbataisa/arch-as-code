# Techcombank Architecture

Architecture-As-Code repository for Design Approval Board (DAB) governance. This
repository is the source of truth for Techcombank's architecture decisions, reusable
patterns, and standards — versioned, reviewed, and built into a documentation site the
same way code is.

## What's here

| Directory | What it holds |
| --- | --- |
| [`governance/`](governance/) | The DAB process itself, review standards, and approval criteria |
| [`registry/`](registry/) | Auto-generated indexes of DAB submissions — do not edit by hand |
| [`knowledge-base/`](knowledge-base/) | Architecture principles, design patterns, NFRs, and the [testing standard and archetypes](knowledge-base/testing/README.md) |
| [`domains/`](domains/) | Per-domain architecture (Payments, Core Banking, Lending, Data Platform, Digital Channels, Risk Management, Wealth Management), each with its own DABs |
| [`qe-harness/`](qe-harness/README.md) | A runnable reference implementation of the testing knowledge base's archetypes — a synthetic SUT plus harness modules across JMeter, Gatling+Karate, k6, and Locust |
| [`templates/`](templates/) | Full and light DAB document templates, ADR template |
| [`registry/`](registry/README.md), [`dab/`](dab/) | DAB submission scaffolding and worked example structure |
| [`scripts/`](scripts/README.md) | Validation and generation scripts backing the CI gates below |

## Design Approval Board (DAB)

Significant architecture changes go through a DAB: a folder of numbered documents
(business context, design concerns, architecture, data, integration, infrastructure,
security) reviewed by domain specialists and the EA Board before merge. See
[CONTRIBUTING.md](CONTRIBUTING.md) for the full submission process, and
[`governance/dab-process/README.md`](governance/dab-process/README.md) for what
triggers a Full vs. Light DAB and the approval SLA.

## Building the documentation site

The whole repository is the MkDocs source (`docs_dir: .` in [`mkdocs.yml`](mkdocs.yml)),
so anything you can browse here in plain Markdown also renders as a navigable site with
search, versioning, and Mermaid diagrams.

```bash
pip install mkdocs mkdocs-material mkdocs-mermaid2-plugin pymdown-extensions \
  mkdocs-git-revision-date-localized-plugin mkdocs-minify-plugin mkdocs-exclude
mkdocs serve
```

## Contributing

Read [CONTRIBUTING.md](CONTRIBUTING.md) first — it covers the DAB submission process,
branching strategy, merge request conventions, and writing guidelines. Governance-related
files under `registry/` are generated by CI and should not be edited directly.
